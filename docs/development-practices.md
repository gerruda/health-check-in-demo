# Практики разработки: что сработало, а что нет

Проект собирался как pet-кейс «бот-тренер» с активным использованием ИИ-агента.
Ниже — не реклама, а честный разбор практик: что дало качество, что создало
долг и что пришлось переделывать.

## 1. Что сработало

| Практика | Что дала |
|---|---|
| **Спецификация раньше кода** | FR/AC в `ТЗ_телеграм_бот.md`, затем фича-доки в `docs/features/*`; меньше «сделал не то». |
| **TDD и регрессии на баги** | Каждый баг из ручного теста получал RED-тест; повторные поломки ловились. |
| **E2E через реальную сборку** | `buildRouter` + временный `DATA_ROOT` + fake Telegram/LLM; забытая проводка (`WithAsk`, `WithReview`) ловится тестом, а не в проде. |
| **Разделение канона и read-model** | Markdown — источник правды, SQLite — производный индекс; rebuild и fallback. |
| **Границы LLM** | Таймауты, валидация мусора, KB-контекст только для осмысленных вопросов, sanitize ссылок/PMID, fallback провайдера. |
| **Vision: сначала код, потом модель** | Структурированное извлечение, проверка диапазонов, удаление «Подход N», дедупликация скриншотов, предупреждение о нераспознанной дате. |
| **Единые часы в тестах** | `WithClock` до экстрактора и команд; тесты не зависят от даты запуска (после одного CI-инцидента). |
| **Quality gates** | `make check`, `make e2e`, `go test -race`, `govulncheck`; линтер с 0 предупреждений. |
| **Разбор инцидентов** | `docs/testing/incident-lessons.md` + `docs/review/bugs.md`; ошибки превращались в правила и тесты. |
| **Наблюдаемость** | Prometheus-метрики, `/healthz`, структурные логи без токенов, деплой-доки. |
| **Бэкапы и ручной тест-план** | `docs/testing/manual-test-plan.md`; проверка на копии данных, а не на проде. |
| **Секреты вне репозитория** | `.env` в `.gitignore`, маскирование токена в логах, allowlist на приватном этапе. |

## 2. Что не сработало или создало долг

| Проблема | Урок |
|---|---|
| **Жёстко зашиты два пользователя** (`athlete`/`wife`) | Для публичного бота нужен tenant-слой с первого дня: `users`, изоляция данных, generic-профили. Переделка дорогая. |
| **Date-зависимые тесты** | Дважды роняли CI при смене недели. Правило: в тестах нет `time.Now()` для окон; только фиксированные часы. |
| **Отчёт перезаписывал машинно-читаемый Markdown** | `TrainingReport` уничтожал `## Упражнения`; история терялась после rebuild. Урок: сквозной тест `write → read → index` для каждого вида данных. |
| **Кэш по mtime каталога** | Внешние правки не инвалидировали кэш; перешли на отпечаток файлов. |
| **Молчаливые дефолты** | Пустая дата скриншота сохранялась «на сегодня»; теперь уточняем дату. «Нет данных» ≠ «значение по умолчанию». |
| **Настройки в одну строку** | `/settings` был нечитаемым; после фидбека — блоки и русские алиасы. UX проверять на человеке, а не только тестами. |
| **Локальная 3B-модель** | Путала креатин/креатинин, иногда долго отвечала; помогли API-режим, таймауты, grounding и честные ограничения. |
| **Дублирование мониторинга** | Сначала стек жил внутри проекта бота, потом переехал в общий `bots/monitoring`; лучше сразу общий, без двух Prometheus. |
| **Бинарь в git** | Собранный `healthbot` попал в коммит и ломал `git pull`; артефакты — только в `bin/`, `.gitignore`. |
| **IP/данные в документации** | Реальный IP засветился в примерах; заменили на `203.0.113.10`, историю веток переписали. В публичных доках — только placeholders. |
| **Сборка на 1 ГБ VPS** | Компилятор убивался OOM; кросс-сборка локально + доставка бинаря. Ресурсы планировать до деплоя. |
| **Docker Snap и относительные пути** | `docker compose` не видел файл из-за cwd snap; помогли `-f /abs/path` и перенос в `/root`. |
| **Лишние прокси/контейнеры** | На VPS остались неиспользуемые mtg/ss-libev/gatekeeper; аудит и остановка освободили память/порты. |

## 3. Что бы сделал иначе

1. Сразу `users` + consent + изоляция данных, даже для «двух человек».
2. Отдельный `testclock` helper и запрет `time.Now()` в тестах окон.
3. Контракт «канон ↔ read-model» и сквозные тесты для каждого типа данных.
4. Общий мониторинг с первого дня; метрики без PII.
5. Секрет-скан и placeholder-IP в pre-commit/CI.
6. Проверка UX на живом человеке после каждой крупной фичи.

## 4. Для ревьюера

- Архитектура: `internal/store` (Markdown+SQLite), `internal/intake` (текст/vision), `internal/llm` (провайдеры+tools), `internal/router` (Telegram), `internal/app` (wiring).
- Надёжность: `docs/testing/incident-lessons.md`, `docs/review/bugs.md`.
- Процесс: `docs/features/*`, `ТЗ_телеграм_бот.md`, `docs/результаты_работы.md`.
- Демо: `docs/demo/`.

Проект — учебно-практический, не медицинское изделие. Скриншоты в демо
синтетические; реальные данные пользователей в репозиторий не попадают.
