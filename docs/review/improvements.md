# Предложения по улучшению и оптимизации

**Дата:** 2026-11-14 · дополнение к [`bugs.md`](bugs.md).

Разделено по слоям. Каждый пункт — не баг, а технический долг или рост качества.

## Данные и хранилище

1. **Единый формат сессии.** Свести generic-шаблон и дневник-отчёт к одной
   схеме разметки (см. BUG-1): `## Итог`, `## Упражнения`, `## Боль`,
   `## Самочувствие`, `## Кардио` — канон; отчёт — только presentation-секция.
   Устраняет рассинхрон reader/writer/index.

2. **Замеры в read-model.** `Reader.Measurements` не кэшируется и не попадает в
   SQLite (`historydb`), в отличие от чек-инов/тренировок. Добавить
   `measurements` таблицу + write-through, иначе `/review` каждый раз
   перечитывает каталог.

3. **Надёжная инвалидация кэша.** Заменить `dirStamp` (mtime+size) на
   отпечаток содержимого каталога (имя+mtime+size каждого файла) или явную
   версию; добавить `-reindex`/TTL. Сейчас корректность зависит от разрешения
   mtime файловой системы.

4. **Инкрементальный sync.** `historydb.Rebuild` делает `DELETE` всего и
   перечитывает всё при каждом старте. Для роста истории — диф по файлам,
   журнал изменений или upsert только изменившихся дат.

5. **Расширяемый реестр пользователей.** `Rebuild` зашивает
   `[]nlu.Person{Athlete, Wife}`. Вынести в таблицу `users` + per-user `flock`
   (этап 3 плана масштабирования), чтобы новый пользователь не требовал
   правки кода.

6. **Конкурентность по chat_id.** `intake.Service.procMu` — глобальный мьютекс:
   один пользователь блокирует обработку другого. Перейти к per-chat очереди
   (уже есть черновик в плане), сохранив один процесс-писатель на файл.

## LLM / качество

7. **Параметры генерации.** `ollamaProvider` не задаёт `Options`
   (temperature/top_p/num_predict). Для экстракции чисел ставить
   `temperature=0`, для чата — ниже дефолта; уменьшит флуктуации парсера.

8. **Разделение моделей.** `/ask` и чат сейчас на `qwen2.5:3b`; при наличии
   `qwen3:8b` использовать более сильную модель для RAG-ответов, а лёгкую — для
   быстрой экстракции. Вынести выбор модели в `.env` уже сделано, осталось
   документально рекомендовать.

9. **Кэш query-embeddings.** `kb.SearchHybrid` на каждый вопрос делает
   отдельный вызов embeddings. Добавить LRU по тексту запроса или вычислять
   вектор один раз для `/ask`, а tool `search_knowledge` переиспользовать.

10. **Единая санитизация текста.** См. BUG-5: сохранять структуру ответа,
    чистить только URL/DOI/PMID; добавить golden-тесты ответов.

11. **Консистентный fallback.** `embeddings` при сбое падает на лексику на весь
    запуск; при `LLM_MODE=api` неочевидно, что embeddings всё равно идут на
    Ollama. Добавить явный `EMBEDDING_MODE` и retry/backoff.

## Поиск по базе знаний

12. **Инкрементальный индекс.** `kb.Load` читает все файлы синхронно при старте,
    embeddings первого запуска занимают ~минуту. Вынести в фоновую загрузку с
    «готовностью», ловить изменения файлов.

13. **Чанкинг по таблицам.** Текущий чанкер делит только по `#`-заголовкам;
    длинные секции с таблицами могут превышать контекст embedding-модели.
    Добавить деление по пустым строкам/максимальному числу токенов.

14. **Ранжирование и оценка.** Ввести набор golden-вопросов и метрику
    hit@k на локальной базе, чтобы рефакторинг поиска не деградировал незаметно.

## Код и тесты

15. **Консолидация дубликатов.** `meaningfulQuestion` (router) и
    `looksLikeKnowledgeQuery` (app) — одна функция (см. BUG-7); формы
    `parseSleepField`/`parseFloatField` пересекаются с text-rules.

16. **CI-цель для E2E.** E2E сейчас исполняется как часть `go test ./...`, но
    явная job `make e2e` + mutation-check (`WithAsk`/`WithReview` убрать → тест
    падает) сделает релизный gate читаемее.

17. **Собственный лимит на размер ответа Telegram.** `sendText` не проверяет
    длину; длинный `/week`+`/review` может упереться в лимит Telegram (4096).
    Добавить чанкинг или осознанное сокращение.

18. **Локализация строк.** `tools/knowledge.go` Description содержит английский
    «citing»; унифицировать русские подсказки и ошибки.

## Наблюдаемость и эксплуатация

19. **Метрики.** Добавить счётчики: время распознавания, доля fallback
    (LLM→правила, embeddings→лексика), ошибки сохранения — для регрессий.

20. **Healthcheck.** `make doctor` есть; добавить отдельный endpoint/лог
    «index ready», «embeddings ready», «last processed update» для дебага
    потерянных сообщений (случай 409 getUpdates).

21. **Ротация логов.** `logs/healthbot.log` растёт без ограничения; задать
    max-size/rotated-файлы или `logrotate`-конфиг.
