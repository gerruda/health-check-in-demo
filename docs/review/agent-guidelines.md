# Инструкции для агентов: как не повторять ошибки и как развивать бота

**Источник:** [`bugs.md`](bugs.md) и [`improvements.md`](improvements.md).
**Статус:** обязательные правила для следующих итераций.

## 1. Что показал аудит (выводы по классам ошибок)

| Класс | Корневая причина | Как ловить заранее |
|---|---|---|
| Расхождение write/read форматов (BUG-1) | отчёт перезаписал канон, reader не понимает отчёт | сквозной тест «write → read» для каждого вида данных |
| Кэш по метаданным ФС (BUG-2) | mtime+size ненадёжны для внешних правок | отпечаток содержимого + TTL/`-reindex` |
| Молчаливые дефолты при неполном извлечении (BUG-3) | date=now при пустом `date_text` | «нет данных» ≠ «значение по умолчанию»: спрашивать/помечать |
| Неверный текст ошибки по типу входа (BUG-4) | один fallback-текст на все типы | формировать подсказку по типу входных данных |
| Пост-обработка ломает структуру (BUG-5) | `strings.Fields` схлопывает `\n` | golden-тесты ответов, санитайзить построчно |
| Проглатывание ошибок чтения (BUG-6) | `continue` без лога | логировать каждый пропуск файла |
| Дублирование эвристик (BUG-7) | две копии «похоже на вопрос» | одна функция + тест, DRY |

## 2. Обязательные правила (чтобы ошибки не возвращались)

1. **Для каждого вида данных — сквозной тест `writer → reader → index`.**
   Проверять, что после всех преобразований (включая `WriteTrainingReport`)
   `Reader.TrainingSessions`/`CheckinValues`/`Measurements` и SQLite возвращают
   те же поля. Никакого «отчёт красивый, а парсер пустой».

2. **Канон и presentation разделены.** Generic-секции (`## Упражнения`,
   `## Итог`, `## Боль`) — машинно-читаемый канон; отчёт дополняет, а не
   перезаписывает. Если решено менять формат — менять reader и writer
   одновременно + миграция.

3. **«Нет данных» ≠ «по умолчанию».**
   Пустой `date_text`/RPE/длительность → уточняющий вопрос или явная пометка,
   а не молчаливый `now`/дефолт.

4. **Инвалидация кэша — по содержимому, не по mtime.**
   Внешние правки Markdown должны видеться без рестарта (или задокументированный
   `-reindex` + предупреждение в логе).

5. **Ошибки чтения/сохранения всегда в лог.**
   Пропуск файла, fallback embeddings→лексика, fallback LLM→правила — каждая
   деградация логируется с причиной; иначе «нет данных» неотличимо от «сломалось».

6. **DRY для эвристик.**
   Одна функция «похоже на вопрос», один список терминов, один парсер
   sleep/float/date; тест на согласованность копий запрещён их существованием.

7. **E2E через реальную сборку роутера (`buildRouter`), с mutation-check.**
   При добавлении команды/формы/маршрута — тест, что без wiring падает.

## 3. Как улучшать процесс разработки бота с ИИ-агентом

### Перед кодом

- **Фиксировать контракт формата.** Новый тип данных = сначала пример файла
  Markdown (канон) + как его читать. Отчёт/красивый вывод — вторичен.
- **Спека раньше кода (SDD).** Любое поведение — сначала FR с критериями
  приёмки, потом тест, потом код. Уже принято; сохранять.

### Во время кода

- **TDD со сквозным слоем.** unit (чистые функции) + integration
  (writer→reader→index) + E2E (router). Для багов — RED-тест, воспроизводящий
  именно наблюдаемое поведение.
- **Каждый fallback — явный и логируемый.** `LLM→правила`, `embeddings→BM25`,
  `report→generic`, `index→Markdown` — одна точка, лог с причиной, тест.
- **Один источник времени.** `WithClock` доходит до экстрактора; тесты не
  зависят от реальной даты/часового пояса.

### После кода (Definition of Done)

- `make check`, `make e2e`, `go test -race -count=1 ./...`, `govulncheck`.
- Обновить: `ТЗ_телеграм_бот.md`, `README.md`,
  `docs/результаты_работы.md`, `docs/review/*.md` (если менялись инварианты),
  `CLAUDE.md` (если появился новый класс ошибок).
- Проверить инвариант «канон остался читаемым» после каждого PR с записью данных.

### Ревью-чеклист для агента

- [ ] write и read понимают один и тот же формат (сквозной тест есть)?
- [ ] нет молчаливых дефолтов/пропусков ошибок?
- [ ] кэш инвалидируется надёжно (содержимое/TTL)?
- [ ] fallback-и логируются и покрыты тестами?
- [ ] нет дубликатов эвристик/парсеров?
- [ ] E2E собирает реальный роутер, а не копию?
- [ ] время инжектится, тесты дата-независимы?
- [ ] спека/README/отчёт/уроки обновлены?
