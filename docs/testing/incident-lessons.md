# Инциденты ручного теста: разбор и защита от повторения

**Дата:** 2026-11-14 · **Ветка фиксов:** `fix/manual-test-bugs`, `fix/settings-ux`
**Правило проекта:** найденный баг сначала воспроизводится тестом, потом чинится.
Ниже — ошибки, причины, где закреплено тестами и какое правило добавлено агентам.

## Правила для агентов

1. **Любая команда должна быть проверена через реальную сборку роутера.**
   E2E использует `buildRouter`, а не копию `router.New`: иначе можно снова
   потерять `WithAsk`/`WithReview`/форму. При добавлении команды — тест в
   `internal/app/e2e_test.go` и mutation-check (убрать wiring → тест падает).

2. **Один источник времени.**
   `Service.WithClock` должен влиять и на экстрактор; тесты не используют
   реальную дату. Новая логика с «сегодня/вчера» — только через `s.now()`.

3. **Новая настройка — полный цикл.**
   `settings.Keys` + `Apply` + `Validate` + отображение с русской подписью +
   ключ в заголовке `/settings` + тест `/set`/`/settings` + русский алиас,
   если пользователь видит русское название. Не вставлять ключи в каждое
   значение одной строкой — только заголовки/футер.

4. **Каждый новый тип свободного текста — отдельная эвристика.**
   `LooksLikeX` + маршрут в router + тест, что сообщение не уходит в LLM-чат.
   Пример: питание `2300 ккал, Б…` (BUG-06).

5. **LLM — не источник истины.**
   Таймауты локальной модели: чат/LLM 45 с, `/ask` 60 с (холодный qwen);
   пустой ответ → retry/fallback; мусор не отправлять; KB-контекст только
   для осмысленных вопросов; PMID/DOI — только из контекста.

6. **Vision: сначала код, потом модель.**
   Любые числа/имена из скриншота проверять диапазонами и эвристиками;
   «Подход N», заголовки таблиц и пустые имена не сохранять; дату не
   выдумывать — при отсутствии предупреждать; одинаковые изображения не
   обрабатывать повторно (хэш); тренировочный скриншот не должен создавать
   чек-ин.

7. **Отчёты не изобретают данные.**
   Утренние показатели тренировки — только чек-ин **за ту же дату**, иначе
   «нет данных». Никаких fallback на соседний день. Проверять тестом без
   чек-ина.

8. **Ручной тест — на бэкапе.**
   Перед серией копировать `данные_*`, `база_знаний`, `настройки`; тестовые
   файлы не считать эталоном; профиль жены тестировать из её `chat_id`.
   Один экземпляр бота: два long polling дают 409 и потерю сообщений.

9. **Runtime-каталоги не в git.**
   `настройки/`, `.healthbot/`, `logs/`, `.sandbox-cache/` — производные,
   должны быть в `.gitignore`; ручные тесты не коммитить.

10. **Определение готовности фикса.**
    Баг воспроизведён тестом (RED) → фикс → `make check`, `make e2e`,
    `go test -race ./...`, `govulncheck`; обновлены спека/README/этот файл.
