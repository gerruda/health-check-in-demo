# Фича: автоматический воскресный разбор (FR-3.7)

**Ветка:** `feat/sunday-review` (стек поверх `feat/vector-search`) · **Статус:** готово к PR
**Дата:** 2026-11-12 · **Связанные пункты:** FR-3.7, FR-5.

## 1. Что делает

Каждое воскресенье в заданное время бот сам присылает разбор:

1. **Анализ недели** — `/week` (HRV/зоны, сон, пульс, питание vs цели, тренировки,
   вес, ориентир) за 7 дней.
2. **Замеры** — текущие вес/талия/висцеральный и Δ к прошлому замеру.
3. **Стратегия на следующую неделю** — 2–3 действия:
   - восстановление (2 силовые, без сдвоенных, RPE 6–7, сон 7.5–8 ч) или
     нагрузка (3 силовые + 1–2 кардио, прогрессия при RPE ≤7);
   - белок/дефицит по 7-дневному среднему и целям;
   - замеры: темп 0.5–1% веса, талия/висцеральный приоритет.
4. Тот же текст доступен вручную через `/review`.

## 2. Настройки

Главное — **персональные настройки** (у каждого свой профиль):

| Ключ `/set` | Дефолт | Смысл |
|---|---|---|
| `weekly_review` | `off` | присылать разбор этому человеку |
| `weekly_review_time` | `09:00` | желаемое время ЧЧ:ММ (локальная TZ) |

```
/set weekly_review on
/set weekly_review_time 10:30
/settings   # видно: «Воскресный разбор: вкл · 10:30»
```

Env — только дефолты/мастер-выключатель: `SUNDAY_REVIEW_ENABLED` (общий),
`SUNDAY_REVIEW_TIME` (fallback), `SUNDAY_REVIEW_TZ` (таймзона сервера).
По умолчанию персональный разбор **выключен** — никто не получает его без
явного `/set weekly_review on`.

Состояние отправки — `DATA_ROOT/.healthbot/sunday_review.json` (chat_id → дата),
поэтому рестарт не дублирует сообщение в тот же день. Пустые chat_id
пропускаются; нет данных — разбор всё равно подскажет `/measure`/чек-ин.

## 3. Acceptance

| # | Критерий | Проверка |
|---|---|---|
| AC1 | Отправка только в воскресенье после персонального target; выключенным — нет | `TestRunOnceOnlySundayAfterTarget`, `TestRunOnceUsesPerChatSchedule` |
| AC2 | Повтор в тот же день не отправляется | тот же тест |
| AC3 | Состояние переживает рестарт | `TestRunOncePersistsState` |
| AC4 | `/review` содержит анализ недели и стратегию | `TestReviewShowsDeltasAndActions` |
| AC5 | Конфиг валидирует время/зону | config tests |
| AC6 | `make check`/`-race`/`govulncheck`; PR | CI |

## 4. Границы

- Стратегическая 4-недельная сводка пока не выделена в отдельный блок (backlog).
- Планировщик in-process; отдельный cron/воркер не нужен.
