# Фича: M2 — настройки целей и зон (FR-7, `/set`-хранилище)

**Ветка:** `feat/m2-settings` · **Статус:** готово к PR (проверки зелёные) · **Дата:** 2026-11-12
**Связанные пункты ТЗ:** FR-7 (настройки), §6 (`Settings`), §13 (U13, U14).

## 1. Зачем

Пользователь может менять цели и пороги зон прямо в чате (`/set key value`).
Значения — **переопределения поверх дефолтов контракта** (CLAUDE.md /
CLAUDE-zheny.md / `процедуры`), хранятся в бот-owned YAML:

```
настройки/athlete.yaml
настройки/wife.yaml
```

В этом инкременте — сам слой настроек: модель, загрузка/сохранение, валидация
диапазонов, `auto` для базы HRV, история изменений, защита от опасных значений.
Интеграция `/set`/`/settings` в роутер — следующим PR (сейчас открыт PR
photo-intake, который меняет router/app).

## 2. Ключи и диапазоны (FR-7.2/FR-7.4)

| Ключ | Значение | Диапазон / правило |
|---|---|---|
| `kcal` | целевой калораж | 1200–4000 |
| `protein_min` / `protein_max` | белок, г | 40–300; min ≤ max |
| `fat_max` | жиры, г | 30–200 |
| `carbs_min` / `carbs_max` | углеводы, г | 0–600; min ≤ max |
| `weight_goal` | цель по весу, кг | 40–200 |
| `hrv_base` | база зоны, мс; `auto` — расчёт от 7-дневного среднего | 15–150; `auto` → `nil` |
| `rhr_green_max` | пульс «зелёной» зоны | 35–80, < `rhr_red_min` |
| `rhr_red_min` | пульс красной зоны | 50–120 |
| `hrv_green_margin` | допуск зелёной (по умолчанию 2) | 0–10, < `hrv_red_margin` |
| `hrv_red_margin` | допуск красной (по умолчанию 5) | 1–20 |

Неизвестный ключ, не-число (кроме `auto`), нарушение диапазона или
противоречие min/max → ошибка с объяснением; файл не меняется.

## 3. Поведение

- `Load(person)` — читает YAML; файла нет → пустые настройки (дефолты).
- `Apply(person, key, value)` — валидирует **итоговое** состояние (с учётом уже
  сохранённых значений), пишет атомарно (tmp→rename), добавляет строку в
  `history` (дата, ключ, значение), возвращает новые настройки.
- `Reset(person)` — удаляет файл, возвращает дефолты (FR-7.5).
- `Path(person)` — путь `настройки/<person>.yaml`.
- `Settings.GreenMargin()`/`RedMargin()` — значения с учётом дефолтов (2/5).

## 4. Матрица тестов

| Тест | Что проверяет |
|---|---|
| `TestLoadMissing` | нет файла → пустые настройки, без ошибки |
| `TestApplyKcalAndHistory` | U13: kcal=2400, YAML, строка истории с датой |
| `TestInvalidKcal` | U14: 900/5000 → отказ «диапазон», файл не создан |
| `TestInvalidHRVBase` | U14: 10/14/151 → отказ; 15/150 — ок |
| `TestHRVBaseAuto` | число → `hrv_base_manual`; `auto` → nil |
| `TestApplyAllKeys` | каждый ключ принимается и сохраняется |
| `TestUnknownKey` | неизвестный ключ → ошибка |
| `TestInvalidPerson` | чужой person (`dog`) → ошибка |
| `TestCrossFieldValidation` | protein_min > protein_max, rhr/margins → отказ, файл не меняется |
| `TestReset` | удаление файла, повторный reset без ошибки |
| `TestNoTempFiles` | после записи нет `.tmp-*` |
| `TestDefaultMargins` | дефолты 2/5 и переопределение |

## 5. Что НЕ входит

- Команды `/set`, `/settings`, `/set reset` в чате и `*`-пометки в ответах —
  после мержа PR photo-intake (router/app).
- Применение настроек в анализе зон/питания — M2-часть после интеграции.
- Правки CLAUDE.md/контракта — настройки только бот-owned YAML.
