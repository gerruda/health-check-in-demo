# Фича: дневник-отчёт тренировки + уточнение полей

**Ветка:** `feat/training-report` · **Статус:** готово к PR · **Дата:** 2026-11-12
**Связанные пункты ТЗ:** FR-3.3/3.4, FR-2.2, FR-8.

## 1. Зачем

Тренерский отчёт должен выглядеть как шаблон дневника, а не как короткая
сводка: утренние показатели, разминка, таблица упражнений, кардио, статистика,
анализ и прогрессия за последние 6 тренировок. Плюс бот должен **уточнять**
RPE/длительность/средний пульс, если их не было в сообщении.

## 2. Что делает

- Комбинированное сообщение («запиши чек-ин…, утром тренировка…») сохраняет
  **и чек-ин, и тренировку**; отчёт берёт утренние метрики из чек-ина.
- Файл тренировки перезаписывается полным отчётом:

```text
# Уличная тренировка: 12.11.2026

## Утренние показатели
- HRV: 30 мс (жёлтая зона)
- Пульс покоя: 60 уд/мин (граница)
- Сон: 7 ч 00 мин (норма)

## Разминка/заминка
- Суставная разминка

## Основные упражнения (2 подхода)
| Упражнение | Подходы | Повторения | RPE | Примечания |
...

## Кардио-дополнение
- подъем по лестнице на 32 этаж

## Общая статистика
- Средний пульс: ...
- RPE: ...
- Общий объём: 4 упражнения × 2 подхода = 8 подходов

## Анализ
- ...

## Прогрессия (последние 6 уличных тренировок)
| Упражнение | 10.11 | 12.11 |
...
```

- **Уточнение недостающих полей**: после сохранения, если нет RPE/длительности/
  среднего пульса, бот спрашивает одним вопросом (`pending` в памяти).
  Ответ вида «RPE 7, 45 минут, пульс 120» обновляет тренировку и отчёт,
  не создавая новый файл; «не знаю» — закрывает вопрос.
- Пока ждём уточнение, новые чек-ины/тренировки не перехватываются.

## 3. Acceptance criteria

| # | Критерий | Проверка |
|---|---|---|
| AC1 | Отчёт содержит утро/разминку/таблицу/кардио/статистику/анализ/прогрессию | `TestTrainingReportTemplate` |
| AC2 | Комбинированное сообщение сохраняет чек-ин + тренировку | `TestServiceAsksAndAppliesMissingTrainingFields` |
| AC3 | Нет RPE/времени/пульса → бот спрашивает; ответ обновляет файл | pending tests + live |
| AC4 | LLM не имеет права выдумывать RPE/время при уверенных правилах | `TestServiceDoesNotTakeHallucinatedRPEAndDuration` |
| AC5 | Прогрессия — 6 последних сессий, `—` при отсутствии | report test |
| AC6 | `make check`/`-race`/`govulncheck`; спека/README/отчёт; PR | CI |

## 4. Уточнения после живого теста (v0.15.1)

- «рпе 8» (кириллицей) распознаётся; «время тренировки 40 минут» больше не
  отбрасывается защитой от новых тренировок.
- Кардио-детали из ответа («кардио 10 минут, средний пульс 140») добавляются
  в строку кардио отчёта.
- Разминка определяется **только по названию** упражнения; note «разминка» от
  LLM больше не перекидывает подтягивания/отжимания в разминку.
- Если чек-ина за дату тренировки нет, утренние показатели — «нет данных»
  (не подставляем чек-ин другого дня).
- После уточнения отчёт пересобирается (тест `TestPendingRegeneratesReport`).

## 5. Что не входит

- Автоматический перенос pending через рестарт (in-memory).
- Замена упражнений по инвентарю/боли — следующий слой.
- Отчёт для тренировок из vision использует тот же генератор (путь общий).
