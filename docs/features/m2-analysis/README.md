# Фича: M2 — анализ зон готовности и целей питания

**Ветка:** `feat/m2-analysis` · **Статус:** готово к PR (проверки зелёные) · **Дата:** 2026-11-12
**Связанные пункты ТЗ:** FR-3.2 (зоны от 7-дневной базы), FR-3.5 (питание), §13 (U3–U6), контракт §7.

## 1. Зачем

Чистые функции анализа, независимые от Telegram/файлов (ТЗ §5, §10):
- **зоны готовности** по HRV/пульсу/сну/настроению от персональной базы;
- **цели питания**: ккал/Б/Ж/У, проверка и одна конкретная правка;
- пороги атлета и жены (контракт §7).

Инкремент не трогает router/app (открытый PR photo-intake) — новый пакет
`internal/analysis`. Интеграция в ответы/`/status` — следующим PR.

## 3. Решения

- Пороги передаются структурой `Thresholds`; фабрики `AthleteThresholds(base)`,
  `WifeThresholds(base)` — база берётся из настроек/7-дневного среднего (M2 интеграция).
- Приоритет зон: **🔴 > 🟡 > 🟢** (сначала опасные сигналы). Пересечение
  «пульс 59–60» в контракте (зелёная ≤60, жёлтая 59–62) разрешено в пользу
  явной зелёной границы: жёлтый пульс = (greenMax, redMin] (атлет 61–62).
- «Нет HRV» → `unknown` (зону без HRV не ставим), с пульсом-подсказкой в причине.
- Записи для жены (колени/МЦ) — `Notes`, не меняют зону.
- Питание: цели — из контракта §4; проверка каждого макроса + сводка + одна
  правка (приоритет: ккал → белок → жиры → углеводы); учёт фазы МЦ жены.
